## ファイルのページに最終更新日を出し、ディレクトリだけの入れ子を1行にまとめる
id: 09
branch-slug: dates-and-collapsed-dirs
status: close
type: feat
対象: codeview/repo.py, codeview/build.py, codeview/layout.py, tests/test_build.py, docs/guarantees.md
内容: ファイルのページのヘッダに、そのファイルの最終更新日（HEAD から辿ってそのパスに触れた最後のコミットの日時）を出す。左の一覧には日付を出さない。あわせて、中身がディレクトリ1つだけのディレクトリの連なりを、一覧では `a/b/c` の1行にまとめ、最も深いディレクトリのページへリンクする。
対象外: 中身がファイル1つだけのディレクトリをまとめること（GitHub もまとめない）。最終更新のコミットの題や作者を出すこと。左の一覧とディレクトリのページに日付を出すこと（一覧が詰まるので見送る）。トップのリポの一覧と Issue のページ。拡張の口（`plugins.py`）の変更
仮定: 日時はコミッタの日時（`%ct`）を使う。リポごとに `git log` を1回だけ呼んで全パスの日時を取る（ファイルごとには呼ばない）。shallow clone などで履歴が足りなければ、辿れた範囲の値でよい。ページに静的に書く文字は組み立て時の現在時刻に依らない日付（`YYYY-MM-DD`）にし、相対時刻（`3d ago` 等）への言い直しは既存の `TIME_SCRIPT` に任せる。`--incremental` の出力が付けない build と同じになる保証を崩さないため
確認: `nix develop -c pytest -q` が通る。見本のリポで日時を固定したコミット（`GIT_COMMITTER_DATE`）を作り、ファイルのヘッダに `<time data-ts="<その epoch>">` が出ること、左の一覧には `<time>` が無いこと、`a/b/c/x.txt` だけを持つ `a` が親の一覧で `a/b/c` の1行になり `a/b/c/index.html` へ相対リンクすることを確かめる
人が見るもの: なし（画面は手順3で user が見て、日付をファイルのヘッダだけにすると決めた）

---

### 保証
- 新たに宣言する保証（台帳 §1）:
  - ファイルのページのヘッダの「行数 · サイズ」の並びに、そのファイルに触れた最後のコミットの日時を足す。左の一覧には日付を出さない
  - 静的に書く日付は組み立て時の現在時刻に依らない。`<time>` の `data-ts` に epoch 秒を持ち、JavaScript があれば相対時刻に言い直す
  - 左の一覧で、中身がディレクトリ1つだけのディレクトリは、その子と続けて `a/b/c` の1行にまとめる。連なりは、中身がディレクトリ1つだけでなくなるところで止まる。行は最も深いディレクトリのページへリンクし、件数はその下のファイル数である
  - まとめた途中のディレクトリ（`a/`、`a/b/`）のページも今どおり書き、パンくずはそこへリンクする
- 維持する保証: 台帳 §1 のすべて。とくに「ファイルのページは、ヘッダに行数と（ハイライトできれば）言語を出し…前後のファイル（左の一覧と同じ並び）へのリンクを出す」「README のあるディレクトリのページには…」「本体が書くページの `href` / `src` は…相対パスである」「その相対パスは…実在するファイルを指す」「`--incremental` を付けると…出力は、付けずに作り直したものと同じになる」。§2〜§5 には触れない

### codeview/repo.py

- リポの HEAD から、パスごとの最終更新の epoch 秒を返す関数を足す。`git log --format=<区切り>%ct --name-only -z HEAD` を1回呼び、新しい順に読んで各パスの最初に現れた値を取る。コミットが無ければ空の dict
- マージコミットは既定の `git log` のまま（差分を出さない）でよい

### codeview/build.py

- `build_repo()` で上の関数を呼び、ファイルのページのヘッダに渡す
- まとめの判定は `tree` から行う。子のディレクトリ `c` について、`tree[c のフルパス]` の中身がディレクトリ1つだけなら続けて辿る。行の表示名は `c/d/e`、リンク先は最も深いディレクトリ、件数は最も深いディレクトリのもの（中身が同じなので親と一致する）
- ファイルのページのヘッダに日付を足し、ページに `TIME_SCRIPT` を含める

### codeview/layout.py

- `file_head()` に日付を足す。今の `_time()` は組み立て時の相対時刻を書くので、静的な文字が現在時刻に依らない版を使う（`_time()` 自体は Issue のページが使っているので振る舞いを変えない）
- 子の表示名に `/` を含む行（まとめた行）を描けるようにする。並びは今どおり、ディレクトリが先、名前の大小を無視した順

### tests/test_build.py

- 上の保証ごとにテストを足す。見本のリポに、日時を固定したコミットを2つ以上（別々のファイルに）作り、ヘッダの `data-ts` を確かめる。左の一覧に `<time>` が無いことも確かめる
- まとめは、`a/b/c/x.txt` だけを持つ `a` と、`p/q.txt` と `p/r/s.txt` を持つ `p`（まとめない）を並べて確かめる
- `test_incremental_build_matches_full_build` と `test_links_are_relative_and_resolve` が、まとめた行と日付を含む見本でも通ること

### docs/guarantees.md

§1 の箇条と表に、上の「新たに宣言する保証」と対応するテストを足す。
